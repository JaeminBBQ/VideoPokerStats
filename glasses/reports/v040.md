## Design
- **`src/core/code.ts` (new, pure, immutable):** `stepCode(code, entry, gesture) → { code, entry }`, where
  `CodeState = { step: 'group'|'rank'|'suit', group, cursor, rank, suit, note }`. Unchanged inputs come back by
  reference. Cards go in only through `Entry.tapCard` (so the armed slot, duplicate rules, and new-hand behavior
  match the phone) and come out only through `Entry.undo` ("back" reopens the most recently entered card, not the
  rightmost one). A complete entry is the result screen, whatever step the code was left in: tap/↑/↓ run
  `Entry.clear` and then count as the GROUP choice, and dbl reopens the 5th card at SUIT. Exhausted ranks are skipped
  when scrolling and when the cursor starts. An exhausted group, or both suits of a color already used, leaves the
  step unchanged and sets `note` (`{kind:'group-used'}` / `{kind:'color-used'}`). The lens renders the note on the
  status line until the next gesture. `gesturesFor(card, entry)` gives the shortest gesture sequence (used by the
  tests and the docs).
- **Store:** `state.code` sits beside `entry`, and `codeGesture(g)` was added. Entry changes made by code entry go
  through the same `setEntry` as taps (persist, analyze on 5 cards, discard stale results). `setEntry`, used for
  taps, tapSlot, undo, clear, and voice, resets `code` to GROUP, and so does a hydrate that changes the hand. A code
  gesture also dismisses a voice error. `nextHold/prevHold/resetHold` are kept, but no input maps to them. The API
  doc comment is updated.
- **Input (`core/input.ts`):** CLICK→`tap`, SCROLL_TOP→`up`, SCROLL_BOTTOM→`down`, DOUBLE→`double` (checked
  before tap). Long press and release still drive voice. The gate now drops only the same action within ≤
  `DUPLICATE_MS` = 80 ms, the swipe cooldown is that same constant, and lifecycle events still dedupe at 600 ms.
- **Lifecycle (`bridge/lifecycle.ts`):** the exit flow is removed (`shutDown`, `rebuild`, `exitPending`,
  `EXIT_STALE_MS`, restore). SYSTEM_EXIT/ABNORMAL_EXIT still tear down. FOREGROUND_ENTER resyncs and
  FOREGROUND_EXIT cancels voice. Every raw event is logged at debug level as
  `input {sysType,textType,action,accepted,t,dt}`, including dropped events. `bridge/glasses.ts` lost the
  `shutDownPageContainer` and `rebuildPageContainer` port methods.
- **Lens (`core/format.ts`):** the status line (line 3) is `GROUP|RANK  card n of 5` or `SUIT for 10  card n of 5`.
  A note or a voice message replaces it, and voice wins. Below it go the gesture lines (`tap  A K Q J`,
  `↑  10 9 8 7`, `↓  6 5 4 3 2`, and `dbl  back: fix Q♠` when there are cards), `[10]  9  8  7` with
  `↓ next  ↑ prev   dbl select   tap back`, or `↑ red  [♥]  ◆`, `↓ black  ♠  ♣`, `dbl select   tap back`. Used
  suits show as `-`, and gesture columns are pixel-aligned with pretext. During SUIT the hand line shows the
  pending rank in its slot (`K♠ Q♠ T? _ _`). The result page gains `next: tap / ↑ / ↓   dbl: fix last card`. ↑
  and ↓ exist in the firmware font (getAdvW 224); the `up`/`dn` fallback is wired but unused.
- **Docs:** README has a Usage section, SPEC.md's Glasses section carries a superseded-by-CODE.md note, and
  sim-smoke.md/.sh describe and run the gesture flow. DECISIONS.md gains G7. The version is 0.4.0 in
  app.json, package.json, and package-lock.json.

## Tests (233 total)
- `core/code.test.ts` (27 tests) covers every GROUP/RANK/SUIT transition and wraparound in all 3 groups. It also
  covers:
  - exhausted ranks skipped both ways, an exhausted first rank, an exhausted group (synthetic wide entry), and a
    single free rank
  - toggling within a color, jumping between colors, used-suit skipping, and the both-reds and both-blacks notes
  - dbl with nothing highlighted, an armed slot, and the joker as the last card (back does nothing)
  - back from every step, and back walking across cards
  - result-screen new hand ×3 gestures, and fixing the 5th card from the result screen
  - all 52 cards from empty, full real hands, and a 20 000-gesture random walk asserting the invariants and
    never mutating its inputs
- Format adds a glyph check, 8 code-entry layout tests, and an exhaustive test: all 9 games × 9 partial hands
  (including four of a kind, both reds used, and an armed gap) × every code step, cursor, highlight and note ×
  letter suits × 3 engine states × 16 voice states. That is well over 50 000 pages, each ≤ 568 px per line,
  ≤ 10 lines, ≤ 900 bytes, with every glyph present. Lines are memoized and 1 page in 97 gets the full check. The
  test runs in ~9 s. The existing all-games result test now includes the `next:` line.
- Store adds 6 code-entry tests: gesture-only hand = the same analysis and persistence as taps; result-screen
  fix and new hand; notify counts; interleaving with tap, tapSlot, undo, clear, and voice (a rejected voice entry
  keeps the step); hydrate.
- The input and lifecycle tests were rewritten for the new mapping, the 80 ms gate, the debug timing log, "double
  never exits", and voice not being cancelled by dbl.

## Gesture counts (shortest path, from GROUP)
| Card / hand | Gestures | Count |
|---|---|---|
| A♠ | tap dbl ↓ dbl | 4 |
| 8♥ | ↑ ↓ ↓ dbl ↑ dbl | 6 |
| K♠ | tap ↓ dbl ↓ dbl | 5 |
| J♠ | tap ↑ dbl ↓ dbl (J is one ↑ from A, wrapping) | 5 |
| 3♣ | ↓ ↑ ↑ dbl ↓ ↓ dbl | 7 |
| K♠ Q♠ J♠ 7◆ 3♣ | | 29 |
| A♥ K♥ Q♥ J♥ T♥ | | 24 |

A card takes 4–7 gestures (about 5.6 on average), so a hand takes about 28. On the result screen the first
gesture of the next hand also counts as its GROUP choice.

## Hardware unknowns (owner to check on G2 + R1)
- **Swipe direction:** SCROLL_TOP = ↑ follows the simulator. If the R1 feels reversed, flip `SWIPE_MAP` in
  `core/input.ts`.
- **Double tap firmware behavior:** if the firmware sends a CLICK before DOUBLE_CLICK on real hardware, every dbl
  would also act as a tap. Look at the debug `input` log, where dt between the CLICK and DOUBLE would be small.
- **The 80 ms duplicate window:** real duplicate gaps and the fastest deliberate ↓ ↓ are unmeasured. Tune
  `DUPLICATE_MS` from the debug log.
- **System tap-then-hold exit:** we assume it arrives as SYSTEM_EXIT, which tears down as before. It is
  unverified, and the simulator can't send it.
- **Ring vs temple:** both are treated the same (eventSource is still logged only).
